# Public Launcher Python Removal Migration

The launcher executes native Rust for every existing release/build stage and the
agent workflow. Former Python implementation and test files have been removed
after their behavior and assertions were ported; the inventory below records
that parity review. There is no runtime fallback.

## Module And Command Map

| Legacy module | Native implementation |
| --- | --- |
| `ci/bootstrap.py` | `src/input.rs` strict request/authority, `src/source.rs` checked Git acquisition/closure/ancestry, `src/guards.rs` handle identities and frozen native tool closure, `src/process.rs` bounded private processes and tree cleanup, `src/launch.rs` resolver/native build/dispatch/diagnostics. |
| `ci/validate_release_source_approval.py` | `input::validate_approval`, `launch::write_outputs`, public `approve-source`. |
| `ci/agent_authority.py` | `agent::read_pin/approved_source/validate_authority`, public `agent-source` and separate `agent-run` authority. |
| `ci/verify_agent_handoff.py` | `agent::package_names/payload_names/verify_handoff`, strict recursive duplicate-key parser and public `verify-agent-handoff`. |
| `ci/seal_diagnostics.cjs` | Existing Node sealer and its real cryptographic tests are retained; no Python. |

See README.md for exact CLI/env handoff. The private coordinator must implement
`omni-release run --root SOURCE --work-dir WORK` and
`omni-release agent-run --root SOURCE --work-dir WORK`. Unknown private stages
must fail. Actual application, provider, installation, signing, storage and
publication validation belong to those private commands and remain mandatory;
this public launcher never emits substitute release receipts.

## Explicit Runtime Changes

- The former SOURCE_ENTRYPOINT value is no longer requested, accepted, or
  forwarded. The hardcoded native manifest and committed lockfile replace
  reviewed script loading. The frozen region is the complete
  reviewed tools tree and its parent tools directory; source root remains usable
  by the real application builder. Source/tool bytes and handle identities are
  rechecked before Cargo, after compilation and after dispatch.
- Website token/key handling moves from the private Python entrypoint to the
  public exact-URL/SSH acquisition code. The already-pinned materialized gitlinks
  cross the handoff, while checkout keys/tokens and Actions command files do not.
  This preserves the deferred SSH support and narrows credential exposure. The
  protected agent source-build step receives the same existing submodule secrets.
- setup-python and its version-specific fixture assertions become mandatory
  native validation dispatch. Protocol/provider/hardware test coverage remains
  required in the private validation/transport/installation implementations;
  missing evidence is not accepted by any public workflow gate.
- Numeric MSI bounds, exact package inventories, duplicate JSON rejection and
  stable per-file identities replace the legacy handoff verifier without changing
  its unsigned/not_performed manifest schema or public package destinations.

## Concrete Verification

`CARGO_BUILD_JOBS=1 bash ci/test-native-release.sh` runs locked Rust tests,
format checking and clippy -D warnings with Python/pip/pypy/py commands blocked.
Use the authorized private TMPDIR on the development host. No legacy test is
executed. Structured YAML tests compare exact protected dependency, matrix,
permission, input, evidence and artifact contracts. Existing Node encryption and
relay suites remain workflow requirements.

The runner fixtures use actual local Git commits, ancestry, gitlinks and locked
Cargo builds, including real build scripts that reject secret/config injection.
A public synthetic CLI verifies run/agent-run argv/environment and output
confinement. Only remote transport is redirected to local Git and already-pinned
toolchain installation is adapted; actual Cargo compilation/tests execute. This
is launcher contract evidence, not application-release evidence. POSIX signal,
symlink and complete acquisition fixtures run on Unix. Windows handle/file/job
tests run in the retained Windows contracts matrix. Windows cross-target checks
are useful compile evidence but do not claim native Windows execution.

## Remaining External Acceptance

The existing approved agent source predates the complete native CLI and must be
updated by its owner to a reviewed source containing that CLI and Cargo.lock.
Full release source approval and the source's public-builder gitlink must bind
the reviewed builder revision; activation cannot bypass those checks. The
private dispatcher/families require cross-repository integration by their owners.

This worker does not claim physical-device, real provider, signing, Apple
delivery, installation, publication or remote release success. Those protected
jobs still require genuine evidence. No credentials, account/provider settings,
production resources, private application code or legacy Python files are
modified by this migration worker.
